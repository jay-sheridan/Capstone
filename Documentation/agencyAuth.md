# InspectionAgency Authentication (project-accurate)

This document describes the InspectionAgency (agency) authentication endpoints implemented in this project. It is derived from the actual controller and DTOs under `src/main/java/ca/cars365` so the paths, request fields, validation rules and response shapes match the code.

Base URL
- Local (example): `http://localhost:8080`
- Authentication controller base path: `/api/v1/auth`

Summary
- Agency registration: POST /api/v1/auth/agency/register
- Agency login (authenticate): POST /api/v1/auth/agency/authenticate

Important: The controller methods return a 200 OK with an `AuthenticationResponse` that contains a single `token` field when successful. Validation problems, conflicts and credential errors are handled by `GlobalExceptionHandler` and return structured error objects.

Token details
- The returned token is a JWT generated by `JwtService` and contains at least these claims:
  - subject: username (for agencies this resolves to the entity username as implemented)
  - role: authority string (from granted authorities)
  - accountType: the account type string (e.g. `INSPECTION_AGENCY`)
- Token expiry (as implemented): generated expiration = now + 1000 * 60 * 60 * 24 (24 hours)

-------------------------------

1) POST /api/v1/auth/agency/register

Purpose
- Register a new InspectionAgency and receive an authentication token.

Request
- Headers: `Content-Type: application/json`
- Body: JSON matching `InspectionAgencyRegistrationRequest` fields and validation rules.

Request JSON (example):
{
  "name": "Precision Inspections Ltd",
  "address": "123 Inspection Ave",
  "city": "Toronto",
  "provinceState": "Ontario",
  "postalCode": "M5V 2T6",
  "country": "Canada",
  "licenseNumber": "LIC-2026-98765",
  "password": "Secur3Pass",
  "email": "agency@example.com",
  "phoneNumber": "4165550123",
  "contactPersonName": "Jane Doe"
}

Field validation (from DTO annotations)
- name: NotBlank, max 150 chars
- address: NotBlank, max 255 chars
- city: NotBlank, max 100 chars
- provinceState: NotBlank, max 100 chars
- postalCode: NotBlank, regex `^[A-Za-z0-9\s-]{5,10}$` (5–10 alphanumeric / spaces / hyphens)
- country: NotBlank, max 100 chars
- licenseNumber: NotBlank, length between 5 and 50
- password: NotBlank, @Size(min = 8) and Pattern `^(?=.*[A-Z])(?=.*[0-9]).{6,}$` (requires at least one uppercase and one digit; size constraint enforced by @Size)
- email: NotBlank, valid email format
- phoneNumber: NotBlank, regex `^[0-9]{10}$` (exactly 10 digits)
- contactPersonName: NotBlank, max 150 chars

Response (success)
- Status: 200 OK
- Body: `AuthenticationResponse` (single field `token`)

Example success response:
{
  "token": "eyJhbGciOiJIUzI1NiI..."
}

Possible error responses
- 400 Bad Request (validation failure)
  - Body: `ValidationErrorResponse` with fields: timestamp, status, errorType, message, missingRequiredFields[], fieldErrors{ field: [messages] }
  - Example:
  {
    "timestamp": "2026-03-30T12:00:00",
    "status": 400,
    "errorType": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "missingRequiredFields": ["phoneNumber"],
    "fieldErrors": {
      "phoneNumber": ["Phone number must be 10 digits"]
    }
  }

- 409 Conflict (account already exists)
  - Thrown when an agency with the same license number already exists.
  - Body: `ErrorResponse` (message, status, timestamp, errorType)
  - Example:
  {
    "message": "Inspection agency with this license number already exists!",
    "status": 409,
    "timestamp": "2026-03-30T12:01:00",
    "errorType": "AccountAlreadyExistsException"
  }

Notes
- The service method `registerInspectionAgency` persists the entity and returns a token created by `JwtService`.

2) POST /api/v1/auth/agency/authenticate

Purpose
- Authenticate an existing InspectionAgency using license number + password. Returns a JWT token on success.

Request
- Headers: `Content-Type: application/json`
- Body: JSON matching `InspectionAgencyLoginRequest`:
  - licenseNumber (string)
  - password (string)

Request JSON (example):
{
  "licenseNumber": "LIC-2026-98765",
  "password": "Secur3Pass"
}

Response (success)
- Status: 200 OK
- Body: `AuthenticationResponse`:
{
  "token": "eyJhbGciOiJIUzI1NiI..."
}

Error responses
- 401 Unauthorized (invalid license number or password)
  - Thrown as `InvalidCredentialsException` and handled by `GlobalExceptionHandler`.
  - Body: `ErrorResponse`
  - Example:
  {
    "message": "Invalid license number or password",
    "status": 401,
    "timestamp": "2026-03-30T12:05:00",
    "errorType": "InvalidCredentialsException"
  }

- 400 Bad Request (if the request body is invalid JSON or fails validation when annotations are present)

Notes
- Authentication is implemented by checking repository lookup by license number and matching the stored `passwordHash` via the configured `PasswordEncoder`.
- On success the returned JWT includes `role` and `accountType` claims. The `accountType` is `INSPECTION_AGENCY` for agency tokens.

-------------------------------

Error payload shapes (from the code)

1) ErrorResponse (used for many custom exceptions)
- Fields:
  - message (string)
  - status (int)
  - timestamp (ISO-local datetime)
  - errorType (enum name from `ca.cars365.enums.ErrorType`)

Example:
{
  "message": "Invalid license number or password",
  "status": 401,
  "timestamp": "2026-03-30T12:05:00.123",
  "errorType": "InvalidCredentialsException"
}

2) ValidationErrorResponse (returned when `@Valid` fails)
- Fields:
  - timestamp
  - status
  - errorType (should be `VALIDATION_ERROR`)
  - message (human explanation)
  - missingRequiredFields (array of field names that were NotBlank/NotNull)
  - fieldErrors (map of field -> array of validation messages)

Example:
{
  "timestamp": "2026-03-30T12:00:00",
  "status": 400,
  "errorType": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "missingRequiredFields": ["password"],
  "fieldErrors": {
    "password": ["Password must be at least 8 characters", "Password must contain at least one uppercase letter and one number"]
  }
}

Implementation notes & mapping to code
- Controller: `ca.cars365.controllers.AuthenticationController` (base `@RequestMapping("/api/v1/auth")`)
  - `registerAgency` -> POST `/agency/register` consumes JSON, uses `InspectionAgencyRegistrationRequest`
  - `authenticateAgency` -> POST `/agency/authenticate` consumes JSON, uses `InspectionAgencyLoginRequest`

- Service: `ca.cars365.services.AuthenticationService`
  - `registerInspectionAgency` persists `InspectionAgency` entity and returns `AuthenticationResponse` with token.
  - `authenticateInspectionAgency` looks up by licenseNumber and validates password, returns token on success.

- DTOs:
  - `ca.cars365.dto.request.InspectionAgencyRegistrationRequest` (see field-level validation above)
  - `ca.cars365.dto.request.InspectionAgencyLoginRequest` (licenseNumber, password)
  - `ca.cars365.dto.response.AuthenticationResponse` (single `token` field)
  - Error DTOs: `ErrorResponse`, `ValidationErrorResponse`

- Exceptions handled by `ca.cars365.exception.GlobalExceptionHandler`: `AccountAlreadyExistsException` -> 409, `InvalidCredentialsException` -> 401, `MethodArgumentNotValidException` -> 400, `InspectionAgencyNotFoundException` -> 404.
